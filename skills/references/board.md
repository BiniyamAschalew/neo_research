# Board conventions (shared by every skill)

All generated research state lives under `__board__/` at the project (or worktree) root; `.agents/`, `.claude/`, `.codex/` hold behavior only. Skills create `__board__/` and only the sub-folders they need, lazily, and never overwrite another agent's board file.

```text
__board__/
  PROJECT.md          project specifics (committed); read at startup
  project.env         CONDA_ENV, SLACK_WEBHOOK_URL, WANDB_URL (never committed, never printed)
  STATUS.md           current phase, recent work, next steps
  TRACKER.md          main checkout only: branches and worktrees (generated by ar_tree)
  ideas/, branches/   main checkout only: summaries of closed ideas and branches
  ideas/I###-<slug>/idea.md  living question, theory, evidence and current conclusion
  ideas/I###-<slug>/papers/  reference PDFs and one detailed summary.md
  plans/vN.<slug>.md  plans (with plans/vN.<slug>/ for figure previews)
  reports/<plan>/     report bundle: <plan>.md, figures/, tables/, local/ (ignored raw outputs)
  notes/NN.<slug>.md  focused technical notes
```

Plan and report versions `vN` number board files only; code and configs are organized by entity, never by version ([code style](code-style.md)).

Idea IDs are stable and project-wide, including worktrees. `IDEA.md` points to the living document. Plans/reports must link its ID and specific hypothesis; `ar_dev` updates a brief report takeaway in the idea. Closing an exploration preserves its idea, papers and linked board evidence on main, alongside the legacy close summary.

Project `.gitignore` allows only itself and curated `__board__/` content. Private `project.env`, agent settings/inboxes, backups and raw `local/` outputs remain ignored. Source and configs remain local; published source excerpts may live inside report bundles. The shared neo_research checkout continues tracking its framework code. Previously tracked ignored files require `ar_init --untrack` and a commit; existing project history is retained.

When `STATUS.md` is missing, create it:

```markdown
# Project Status

**Last Updated**: YYYY-MM-DD
**Current Phase**: Setup

## Recently Completed
_None yet._

## In Progress
_None._

## Next Steps
- [ ] Create the first plan.

## Known Issues
_None._
```

Update it at the end of each skill run: date and plan, phase, the last 3 completed items with their report paths, in-progress work, next steps from the report, known issues. It is a projection, not a report.

Every plan, report and note starts with a short part a newcomer can read in a minute (the Experiment Card for plans and reports, a TL;DR for notes), then a line containing only `======`, then the full detail.
