# Compaction (step 1 of ar_branch and ar_merge)

Code moves up one tier at a time: worktree (candidate idea) → branch `b<i>/<name>` (method section) → main (paper). Each move is a compression: what arrives is smaller and cleaner than what left, with the same results. Read [code style](code-style.md) first.

For results-only projects, compare local source files directly: Git diff/commit ancestry cannot detect ignored-code changes. Record source paths and SHA-256 fingerprints in `COMPACTION.md` and the review receipt, and recheck them before a local source transfer; any changed fingerprint requires renewed parity/review. Commit only board receipts; transfer approved code locally as described by `ar_branch`/`ar_merge`.

1. **Decide what survives, with the human.** Read the reports (or, for a branch, its idea summaries), `structure.md` and `git diff --stat <target>...HEAD`. List the components the claimed result depends on: the winning variant, its data path, metric and the experiment configs that reproduce the headline result. Everything else (rejected variants, sweeps, debug scaffolding, one-off analysis, duplicated helpers) goes. Show the keep/remove list and the result to preserve (experiment, metric, value) before rewriting.
2. **Freeze the reference.** On the current commit, run the target experiment's tiny profile and the planned tests with fixed seeds; save the resolved config and outputs under `__board__/compaction/before/` (git-ignored `local/` for large files).
3. **Rewrite.** Delete removed components and their configs; fold the survivors into the entity folders, base classes and `utils/<topic>/`; register them in `_build.py`. Merge duplicated logic, remove dead branches, variant flags and needless checks; prefer batched/vectorized operations where results are identical. Keep config keys, seeds and metric definitions. Do not change algorithms, defaults, splits or metrics: a changed result is a compaction bug unless the human approves it separately.
4. **Prove parity.** Rerun the same tiny profile and tests into `__board__/compaction/after/`; metrics must match exactly or within a stated tolerance. Before `ar_merge`, or when the human asks, also rerun the headline experiment's full profile once and compare with its report.
5. **Record.** Refresh `structure.md`; write `__board__/COMPACTION.md` (date, agent, base, kept, removed, size before/after from `git diff --stat`, parity numbers, full-profile check) and commit it with the rewrite, last. `ar_tree branch|merge` refuse if any code was committed after it.
