# AutoResearch Claude Adapter

This project uses AutoResearch to coordinate Claude, Codex, and the human through a shared board.

## Shared Board

All project state generated by agents must live under `__board__/` at the project root:

- `__board__/STATUS.md`: shared project status.
- `__board__/plans/`: iteration plans.
- `__board__/reports/`: implementation reports.
- `__board__/notes/`: technical notes.
- `__board__/refs/`: project reference material.

Do not write generated research state into `.claude/`, `.codex/`, or `.agents/`.
Those directories define agent behavior and configuration only.

Do not create `__board__/` during ordinary session startup. AutoResearch commands create it lazily when invoked and create only the subdirectories required by that workflow.

## Session Startup Checklist

At the beginning of a Claude session:

1. Read this file.
2. Read `__board__/STATUS.md` if it exists.
3. If executing a plan, read the relevant file in `__board__/plans/`.
4. Scan recent files in `__board__/reports/` and `__board__/notes/` when they are relevant.
5. Do not create `__board__/` during startup. Let the invoked AutoResearch command create only the paths it needs, and never overwrite existing board files during bootstrap.

## Claude Commands

Use the AutoResearch command names:

| Command | Usage | Description |
|---------|-------|-------------|
| `/ar_plan <task>` | `/ar_plan Implement preprocessing` | Generate a plan under `__board__/plans/` |
| `/ar_dev [plan]` | `/ar_dev v3.preprocessing` | Execute a plan and write a report under `__board__/reports/` |
| `/ar_note <topic>` | `/ar_note optimizer comparison` | Write a technical note under `__board__/notes/` |
| `/ar_notify [note]` | `/ar_notify experiment finished` | Send a notification when configured |

Codex uses matching skills instead of slash commands: `$ar_plan`, `$ar_dev`, and `$ar_note`.

## Python Environment

Use the existing project environment when one exists. Prefer `uv` when available, but `pip install` is allowed when necessary.
Document any dependency installation in the relevant report or note.

Common commands:

```bash
# Activate an existing venv if present
source .venv/bin/activate

# Preferred when uv is available
uv pip install -r requirements.txt
uv pip install <package>

# Allowed when necessary
pip install -r requirements.txt
pip install <package>
```

## Development Rules

- Read the relevant plan before editing code.
- Keep changes scoped to the selected plan unless the user explicitly expands scope.
- Run relevant tests after modifying code. If tests cannot run, document why in the report.
- Save plans, reports, and notes under `__board__/`.
- Do not overwrite another agent's board file unless the human explicitly asks.
- Do not run `git push` without explicit human instruction.
- Preserve existing project code style and conventions.
- When a requirement is ambiguous during `/ar_dev`, make a reasonable decision, proceed, and document the decision in the report.

## GPU Jobs: Notify persist.py

`/home1/irteam/data-vol1/persist.py` fills idle GPUs with synthetic load (~90% memory). Any GPU job (training, eval, inference, benchmarks) MUST notify it before touching the GPU, or it may OOM:

- Shell: `python /home1/irteam/data-vol1/persist_notify.py run -- <your command>`
- Python: `sys.path.insert(0, "/home1/irteam/data-vol1"); from persist_notify import gpu_claim` then `with gpu_claim("<exp-name>"): ...`
- Manual: `persist_notify.py start <tag>` before, `persist_notify.py done <tag>` after.

persist pauses within ~2s on a claim and resumes when the claim is released. Unannounced jobs are only detected by an nvidia-smi check every 30s.
