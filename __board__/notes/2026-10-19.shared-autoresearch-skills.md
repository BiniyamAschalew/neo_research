## Project-specific behavior

Canonical workflow text contains no local project names, model names, absolute host paths or fixed hardware allocation. Project root is determined from the active task, not the shared installation location. Applicable AGENTS/Claude instructions, user amendments and local artifact policies retain authority. Structure-map maintenance is incremental; verification remains scoped. Default Python root/config conventions adapt to established entrypoints and report layouts.

The shared artifact helper accepts the existing plan-basename report layout and a version-directory layout via --report-file; it accepts an established same-stem figure CSV convention. Nested code and hash-manifest-backed bounded fixtures are supported. Existing reports were not migrated. Private raw data, large assets and debug outputs are not made Git-eligible by the link installer.

Only plan/dev/metaplan workflows and shared references were linked. Note and notification commands, local policies, code, data and scientific results remain in place. Narrow Claude-adapter exceptions were appended to the restrictive SelfConsistency and Longitudinal Git allowlists. Other original ignore rules were retained.

## Portability

Keep the shared checkout at the linked relative location on another machine, or run the installer to rebuild links for that layout. From the shared checkout: python scripts/link_project_skills.py --apply . ../your-project. Moving sibling checkouts together preserves relative links. A standalone project clone needs the shared checkout to resolve its links.
